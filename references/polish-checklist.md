# 打磨清单

## 布局体检（每批都跑）

在 375、768、1024、1280、1440 五档宽度下，首页每个 section 和每个应用页面（包括弹窗、提示、空状态）都要看：

- 有没有一套固定的间距等级（section 间距、块间距、卡片内边距各用哪几个值），全站统一，没有随手写的数值。
- 标题、正文、按钮之间的垂直间距一致。
- 左右边距对齐在同一条线上。
- 首屏不挤也不空；导航一行放得下。
- 底部导航或悬浮按钮不挡内容，最后一块内容留出底部安全距离。
- 文字不溢出、不被裁切；按钮文字不换行。
- 图片比例不变形。
- 没有横向滚动，没有一侧空一大块。

截图用浏览器的视口模拟。无头浏览器有最小宽度限制，375px 的截图可能被裁，不准。

## 好用

- 数一数核心流程要点几下，能省的步骤都省：记住上次的选择、默认值、一键再来一次。
- 每页只有一个主要动作，按钮文案就是动作本身。
- 关键信息放在首屏（比如取件码、下一步按钮），不要让用户往下找。
- 文案说人话；空状态告诉用户怎么开始；报错告诉用户怎么办。

## 好看

- 一个强调色、一套圆角、一套阴影，全站统一。
- 图标和插图风格统一。
- **能用图片就用生成图**（用户反复强调）：地图底图、插画、场景、装饰、背景、空状态、徽章，一律优先用 生图工具 生成的图片，不用 SVG、CSS 色块或线条画，SVG 的质感比不上图片。SVG 或 CSS 只用在两处：叠在图片上、需要动或随数据变化的东西（路线动画、高亮点、进度），以及操作类小图标。需要动画的画面就做成「生成图做底 + SVG 动画叠在上面」。每批开工前盘一遍还有哪些画面是画出来的，全部列进清单。
- **图片上叠路线、标记、标签时，先定布局再出图**：生成图里路和楼在哪是随机的，先出图再去猜，叠加层一定对不准。做法：
  1. 先画布局草图：用简单线条和方块定好路网、关键地点、路线。
  2. 把草图当参考图喂给 生图工具，要求位置不变，只换成插画或照片质感。
  3. 出图后用程序对齐：按颜色识别出路面（或其他承载区域），路线沿真实的路走，标记放在路线上，标签贴着对应的地点。
  4. 用数字验收，每条都要有数值才算过（只验「在路面上」不够，真实项目就栽在这里）：
     - 路线采样点 ≥ 95% 落在路面上。
     - 端点连通：路线起点到起点地点门口、终点到终点地点门口、中转点（比如驿站）到前后两段路线，像素距离都 ≤ 8px。
     - 中间不断：相邻采样点间距 ≤ 10px。
     - 起点、终点、中转点完整在画框里，不被裁。
     - 底图铺满画框，四边没有空白或白边。
     - 浮层、标签不压住路线和起点、终点、中转点。
     - 有动画时：用动画结束后的最终画面验收；动画过程中再截 2 张，不能出现「看起来断了」的画面。
     - 地点落在对的东西上：每个地点的点都在一栋真实的楼里或门口 8px 以内，不能落在水、草坪、空地上；类型对得上（教学楼放在像教学楼的楼上）。
     - 路线不穿越：路线经过的像素 0% 在水面、楼顶、草坪上。路线用程序在路面区域上寻路（比如 A*），距离、「顺路多走几分钟」按寻出来的真实路径算，不按直线算。
     - 镜头会缩放、旋转、平移时，任何时刻画框里都不露出底图边缘或白边（限制镜头范围，或者把底图出得比画框大一圈）。
     - 每种尺寸的图都要过；放大 2 倍截图再看一遍。不合格就重画或微调。
  5. **demo 只求一眼看明白**：同一页上的几张图可以长得不一样，不用拼成同一个世界，也不用工程级精确。每张图按它要讲的那件事单独画草图，元素越少越清楚越好。不能妥协的只有「看得懂」和「没有常识错误」（地点不在水里，路线不穿楼、不穿湖，两头接上，不露白边）。验收用「3 秒测试」：截图交给一个全新的小评审，只看这一张，答出「谁从哪到哪、关键点在哪、为什么」，并且挑不出不对的地方，就算过；上面的数值检查只用来兜底查明显错误。
  6. **全部实例都要过**：一个页面上往往不止一张这样的图（首屏地图、介绍段地图、列表里的小地图、详情页地图、卡片上的路线缩略），每一张都按这套做和验，不能只修被点名的那张。
  这项检查写进每批自检，不要等评审来发现。评审通常只能看到「对不准」这个症状，找不到「先出图后猜位置」这个原因，开发就会反复手动挪坐标。
- **表达内容的图标也算画面**：规则分类、状态（取件、送达、申诉、隐私）、徽章、加急标记、空状态、底部导航、庆祝效果这些图标，都用生成图，成套出（同一风格、同一尺寸、透明底），和已有生成图标统一。只有**操作符号**保留 SVG 图标库：返回、关闭、勾选、下拉、加减、星级、箭头、搜索、刷新。
- **怎么盘点**：每批开工前，在代码里搜 `<svg`、图标库的 import（比如 `@phosphor-icons/react`）、CSS 渐变和画出来的装饰，逐个判断是「操作符号 / 叠加动画」还是「画面」，画面全部列进这批清单。
- 出图顺序：先试 生图工具（各引擎都试，额度时有时无）；失败了用浏览器的 ChatGPT、Gemini 或 Grok 网页版；换图必须换文件名。
- 数字用等宽数字，金额和分数对齐。

## 流畅

- 切页不闪白、不跳动；骨架屏的形状和真实内容一致。
- 按下有触感反馈（轻微缩放或下沉）；提示不堆叠、不挡内容、按时消失。
- 动效用 spring、时长短；只动 transform 和 opacity；尊重 prefers-reduced-motion。
- 部署后旧缓存导致白屏的情况要防住（加载失败自动刷新、保留上一版打包文件）。

## 想回来

- 进度提醒：订单或任务走到哪一步。
- 成长：等级、积分、信用的进度条，以及离下一级还差多少。
- 成就：完成后的小庆祝，要克制。
- 回顾：收入或成果按月、按年汇总。
- 快捷入口：常用任务一键再来。

## 招牌时刻

从核心流程里挑 4–6 个最关键的瞬间，写进日志，逐个打磨：

- 首屏第一眼
- 核心动作完成的那一下（下单、接单、提交）
- 结果揭晓（码、结果、匹配）
- 价值流动（钱、积分、信用变化），数字滚动和状态变化要看得见
- 页面之间的转场

标准是让人感觉踏实、爽快、想多点两下，而不是炫技。

## 操作后的状态也要体检（一次「全部检查过」之后，用户一眼挑出的问题）

- 只截初始示例数据下的静态页面不够。体检要把导览按两种身份完整走一遍，**每一步操作后都截图**；每种业务状态（比如订单的待接单、进行中、待确认、已完成、已退款、已取消、申诉中）在列表和详情都要截到；高亮、选中、展开、弹窗、提示、空状态都算。
- 程序检查除了横向溢出，还要查**被裁掉的描边和阴影**：每个带 border、outline、box-shadow 或圆角的元素，算出含描边和阴影的完整外框，和最近一个 overflow 不是 visible 的祖先的裁剪框比较，超出就记问题。图标超出所在胶囊、标签也照此查。
- 同类元素样式要统一：同一张卡片里的类型标签和状态标签用同一种胶囊；副标题不要重复标题里已有的信息。

## 演示引导要「指哪点哪」（用户亲自走一遍的反馈）

- 给评审或面试官用的演示原型，引导不能只是一行文字说明。每一步都要直接标出要点的元素（发光描边或光圈加箭头气泡「点这里：发布」），目标不在屏幕里就自动滚过去；切身份、输入码、打分这种步骤，同样直接高亮对应控件，要填的值写在气泡里。
- 先问再引导：第一次进来弹一个小窗问要不要指引（「带我走一遍」/「我自己逛逛」），接受才开始，拒绝就不打扰；记住选择，并留一个随时能重新开始的「新手指引」入口。不要一进来就强行开始引导。
- 验收：开一个全新子代理，只告诉它「跟着屏幕上的提示走完」，不给任何其他说明，手机版和电脑版各走一遍。中途卡住、不知道点哪，就算不过。

## 手机版和电脑版（演示用的原型）

- 同一个产品、同一份数据，做手机版和电脑版两种界面，不要拆成两个 App，也不要为了演示做「两台手机并排」。
- 让看的人自己选：入口处给两张卡片（各配预览图和一句话），进去后顶部还能随时切换，数据和当前页面不丢；两种界面各有可以单独分享的地址。默认按设备选，但任何设备都能切。
- 电脑版要真的按电脑排版（比如左侧导航、中间列表、右侧详情），不是把手机界面放大。在手机上选了电脑版，要能看清，或者提示「电脑上看效果更好」。
